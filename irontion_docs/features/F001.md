# F001: Time Block Feature (Blocos)

This window page will have a daily time-blocking grid.

> [!info] Grid Overview
> - Each cell = **10 minutes**
> - Each row = **6 cells** = **1 hour**
> - Total rows = **24** (00:00 to 23:00)
> - Total cells = **144** (24 × 6 = 1,440 minutes)

## Cell Index Formula

- Index `n` ranges from 0 to 143
- Hour (row) = `floor(n / 6)`
- Slot (column) = `n mod 6`
- Start minute = `n × 10`

## How It Works

The grid works by **selecting first, then choosing what to do**. There are no tools to switch between.

1. **Select** blocks: click one, or drag across several.
2. An **options panel** appears with what you can do with the selection.
3. Choose an action. The selection clears and the grid shows the result.

**Selecting adds; it never cancels.** Pressing another block or dragging another range **adds it** to what is already selected, so many blocks can be picked in any places. The selection stays until you clear it **on purpose**.

| Select | How |
| ------ | --- |
| One block | Click. It selects **exactly that one cell**, never its neighbours of the same activity (sometimes the user wants a single block) |
| Another block | Click it: **added** to the selection |
| A range | Drag across cells, also across hours: **added** to the selection |
| Take a block out | Click a block that is selected (just that one) |
| Extend a range | `Shift`+click, or `Shift`+arrows (from the last block you picked; Shift again can shorten it) |
| Several in a row | Drag across them, or `Shift`+click |
| One cell in or out | `Ctrl`+click (same as a click) |
| **Clear** | The **X** in the panel, **Deallocate activities**, or `Esc`. Allocating also clears, once the blocks have their activity |

### The options panel

Shown while something is selected (see the references below).

- **Stats:** blocks, time, and share of the day (e.g. 4 blocks, 40 min, 3%), plus the time span when the selection has no gaps
- **Contains:** which activities are already in the selection
- **Suggestions:** your most used activities from the last 14 days, one click each (keys `1`–`5`)
- **Allocate activity** (`A`): opens the full activity list ([[F002]])
- **Move blocks** (`M`): click where the blocks should start, or drag a selected cell. Only filled cells move, and they overwrite what they land on
- **Deallocate activities** (`Delete`): clears the selected cells. Always available: when nothing in the selection is allocated, it just ends the selection

## Time Fill

A block is its ten minutes. It fills in as that time goes by, so the grid shows the day as it happens. This is the same idea as the reference: passed time is filled, time ahead is only an outline.

![[F001_00_blocos.jpg]]

| State | Look |
| ----- | ---- |
| **Future** (time not reached) | **Outline only** (a border, no fill). A block planned with an activity has an outline in that activity's color |
| **Current** (the ten minutes now running) | Outline, filling as the minutes pass: 4:00 is empty, **4:05 is half filled**, 4:10 is full. By default it fills **left to right**, the same way the grid reads time |
| **Past** (the ten minutes are over) | **Filled**: the activity's color, or neutral gray when nothing was allocated |

- A day before today is entirely filled; a day after today is entirely outlines.
- The current block updates every 15 seconds. The hour label of the current row is highlighted.
- **Fill direction is a setting** (Settings, Time fill): left to right (default), right to left, bottom to top, top to bottom ([[F003]]).
- Works the same in all four shapes ([[F003]]). The fill and the wave are **clipped to the shape**. In the **glass** the fill is the water: a past block is a full glass, the current one a glass filling up (the surface keeps its gentle wave), a future one an empty glass outline.
- The outline of a future or current block has an **even thickness** (`--block-edge`, 2px) on every shape, in both themes, at any cell size (checked at 36px cells in a 390px window and at large sizes).
- **Water wave:** a gentle wave moves along the surface of the filling block, in whichever direction it fills. It can be turned off in Settings ([[F003]]).
- **Performance:** the 144 cells share **one stylesheet** of clip paths (`blockShapeStylesheet`), not 144 inline SVGs; a past block is one clipped element, a future block two. Only the **current** block ever animates (one element, two thin wave layers) and only on today's grid. Past and future blocks, other days and other pages have no animation at all. It also **pauses while the window is hidden** or minimized, and stops with "reduce motion".
- Logic: `dayProgress()` in `apps/desktop/src/lib/domain/time.ts` (unit-tested, including 4:05 = half).

## Layout

| Window width | Layout |
| ------------ | ------ |
| 896px and up | Grid on the left, options panel and day summary on the right |
| Under 896px | One column. The options panel is a **bottom sheet** (compact: stats, suggestions, actions) and the page scrolls the selection clear of it |
| Under 640px | A tab bar replaces the sidebar. Cells shrink (36px at 390px wide) so six always fit |

## Rules

- Only activities **without sub-activities** can fill cells (see [[F002]]).
- Moving overwrites the cells a block lands on. Moving never leaves the day.
- Blocks can also be deleted in bulk (every block, or the blocks of a date range) from Settings, Danger zone ([[F003]]). The open day reloads right after.
- One action = one save: the grid sends only the changed cells, written in a single transaction. If saving fails, the grid rolls back and shows an error.
