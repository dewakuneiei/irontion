# F002: Activity Feature

Users can create their own activities and assign them to time blocks from [[F001]]. Each activity can contain nested sub-activities and can have tags, so users can organize and filter their time in any way they like.

> [!info] Activity Overview
> - Activities are **created by the user** (no fixed list)
> - Each activity has a **name** and a **color**
> - Each activity can contain **nested sub-activities**
> - Each activity can have **tags** for grouping and filtering
> - Activities are assigned to cells in the Blocos grid (10 minutes per cell)

## Activity Structure

| Field            | Description                                        |
| ---------------- | -------------------------------------------------- |
| `id`             | Unique identifier                                  |
| `name`           | Activity name (e.g., "Schedule", "Drawing")        |
| `color`          | Color used to fill cells in the grid               |
| `parent_id`      | `null` for top-level activity, otherwise parent ID |
| `sub_activities` | List of child activities (nested)                  |
| `tags`           | List of tags attached to this activity             |

## Tag System

Tags are labels that cut across the activity tree. They let users group activities that are in different places in the hierarchy.

- A tag has a **name** (required) and an optional **color**
- One activity can have **multiple tags**
- One tag can be used by **many activities**
- Tags are created by the user and can be reused
- Users can filter the summary by tag (Insights page)
- **Notes use the same tags** ([[F006]]): typing `#name` in a note reuses a tag with that name (ignoring case) or creates one. A note can carry up to 5. Tags created from a note may only use letters, combining marks and digits in any script, `_` and `-`
- Note tags never change the time summaries: notes are not time data

| Field   | Description                         |
| ------- | ----------------------------------- |
| `id`    | Unique identifier                   |
| `name`  | Tag name (e.g., "deep-work")        |
| `color` | Optional tag color                  |

### Tag Examples

- `deep-work`: needs full focus
- `low-energy`: can be done when tired
- `health`: exercise, sleep, meals
- `creative`: drawing, writing, design
- `online`: needs a computer or internet

- **Delegate** (orange)
  - Reply to routine emails `#online`

- **Don't do** (gray)
  - Scroll social media
  - Watch random videos

  - OC artwork `#creative` `#deep-work`

> [!note]
> The structure is fully free-form. Users decide the names, the depth, the colors, and the tags.

- [x] User can create a new activity (name + color)
- [x] User can edit and delete an activity (delete = archive, see Decisions)
- [x] User can add sub-activities inside any activity
- [x] Sub-activities can be nested multiple levels deep (up to 5)
- [x] Sub-activity inherits the parent color by default (user can override)
- [x] User can add, remove, and create tags on an activity
- [x] User can rename or delete a tag (updates all activities and notes using it; deleting keeps the activities and notes)
- [x] The tags panel shows how many activities and notes use each tag
- [x] User selects an activity or sub-activity, then fills cells in the Blocos grid
- [x] Summary shows total blocks per activity, including the sum of its sub-activities

- [x] Suggestions in the create form: starter names (Work, Morning routine, ...) that are not already used

- [x] Starter templates: 67 built-in templates in nine groups, with search and category filter, including the examples above (see [[F005]])

## Decisions

| Question | Decision |
| -------- | -------- |
| Maximum nesting depth? | **3 levels** (top-level = 1). Existing deeper activities keep working; only adding under a level-3 activity is refused |
| What happens to assigned cells when an activity is deleted? | **Archive, keep history.** "Delete" archives the activity and its sub-activities: they leave the tree and the picker, but past blocks and summaries keep them. From the Archived list they can be **restored** (brings back archived parents too) or **deleted forever** (removes blocks; the dialog shows how many). |
| Parent or sub-activity in cells? | **Both.** Any active activity fills cells, so "Don't do" can be picked as well as "Social media" under it. A block on the parent counts for the parent only; the parent's roll-up in Insights adds its sub-activities. Only archived activities are refused. |
| Do sub-activities inherit tags? | **Only when they have none of their own.** A block counts as its activity's own tags; an activity without tags counts as the nearest ancestor's. So "Don't do" (tag A) with "Random videos" (tag B): a block on "Don't do" counts as A, a block on "Random videos" counts as B and **not** A, and "Social media" (no tags) counts as A. Colors inherit the same way. |
| Nested tags (`work/meeting`)? | **No** for now. Tags are flat. |
| Can the user wipe their activities? | **Yes, on purpose, from Settings.** Danger zone → Advanced → Delete data → *All activities* permanently removes every activity (archived ones too) **and all their time blocks**. It shows exact counts and needs a confirmation tick. Tags are kept. This is separate from the everyday "Delete" above, which only archives ([[F003]], Danger Zone). |

## Insights

The Insights page answers "where did my time go?" for a period the user picks. A tag filter and a group-by (activity or tag) work with every chart.

| Period | Shows | Moving |
| ------ | ----- | ------ |
| **Day** (the default: today) | One day | ← → a day at a time; **Today** comes back to today and its progress so far |
| **Week** | Seven days from the user's week start ([[F003]]) | ← → a week; **This week** |
| **Month** | The 1st to the last day | ← → a month (31 January → February); **This month** |
| **Range** | Any two days, **From** and **To** (shared date picker), past or future, at most **366 days** | Moving one end past the other moves both; a too-long range moves the other end. **End today** keeps the length and ends it today |

- Switching kind stays near what is on show: around today if the period has it, else around its first day. A new range starts as the days that were on show.
- A future day is all **Still ahead** in the donut; blocks planned there count for their activity.
- The line under "Hours by activity" says "{duration} tracked today", "... on <day>", or "... over N days".
- Logic: `apps/desktop/src/lib/domain/period.ts` (`periodSpan`, `stepPeriod`, `switchKind`, `currentPeriod`, `setRangeFrom`, `setRangeTo`, `spanDays`), unit-tested; the picker is `components/insights/PeriodPicker.svelte`.

| Chart | Shows |
| ----- | ----- |
| **Share of the day** (donut) | The whole range as a ring. Slices: each **top-level activity** (sub-activities rolled up, same roll-up and colors as the summary), **Other activities** (only while a tag filter hides some), **Unallocated** and **Still ahead** |
| Hours by activity / by tag | The existing bars, and the table beside them |
| **Tracked time by part of the day** | Hours tracked in night (00-06), morning (06-12), afternoon (12-18) and evening (18-24) over the range |
| **Hours per day** | Stacked columns per day by top-level activity (the 6 biggest, the rest as Other). Shown for ranges of 2 or more days |

**The rule for the donut.** The denominator is the **whole range**: days x 144 blocks.

- A block with an activity is part of that activity's slice (a block planned for later today counts for its activity too).
- An empty block that **has happened** (an earlier day, or today up to and including the block in progress) is **Unallocated**: a neutral gray token (`palette.unallocated`, a clearly visible step on both themes, never white on a white card).
- An empty block that **has not happened yet** (later today) is **Still ahead**: a lighter step (`palette.ahead`), so today's chart does not look empty. It is never counted as unallocated.
- The **centre** shows the percent of tracked time: tracked blocks that have happened, divided by the blocks that have happened. With a tag filter, only blocks of matching activities count as tracked; the others become "Other activities".
- The **tooltip** says the activity, its blocks, its duration and its percent of the whole range. The **legend** is sorted by size, with percents.
- A range with nothing tracked is a **full gray ring** (plus the lighter slice for today) and a friendly line with a **Fill blocks** button; the other charts are hidden until there is something to show.

Pure data builders (`apps/desktop/src/lib/domain/insights.ts`: `buildShare`, `buildDailyStack`, `buildPartsOfDay`) take the loaded days and a clock, and are unit-tested: empty range, today with future blocks, a 3-day range, tag filters.
