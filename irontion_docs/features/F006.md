# F006: Notes

Short sticky notes about goals and the day: "Today I will...", "Today I got done...". A note is a few words on a sheet of paper, not a diary. Every note belongs to one day, so it also shows on the Calendar ([[F007]]). **The Notes page and the Calendar are two views of the same notes.**

> [!info] Overview
> - **A board of sticky notes**, as tall as their text (like Google Keep). The user **drags notes to put them where they want**; the order is theirs, not the date's or the creation time's
> - **Pin** a note to keep it at the top; **pick a color** (9) for each note's paper
> - **Every note has a date.** Made on the Notes page it is **today**, and the Notes page never changes it. Only the Calendar picks another day or moves a note ([[F007]])
> - A **reminder** can be set on any note ([[F008]]), a feature of its own, not part of the Calendar
> - **Max 200 characters**, counted as the user sees them. Tags don't count
> - **Tags typed as `#name`** leave the text and become chips; the same tags as activities ([[F002]]), max 5 per note. A **tag panel on the right** filters the board
> - **A paper editor, not a dialog.** The paper holds only the note; Back, save status, color, pin, reminder, date and Delete are **around** it
> - Notes are plain text. No links to activities or time blocks

> [!note] History
> The first version had six templates (Manifest, Done today, ...). They were removed before release: a note is just a sticky note. Migration 006 drops the `template` column.

## The Core Rule: Every Note Has a Date

| Where | The note's date |
| ----- | --------------- |
| New note on the Notes page | **Today** (the user's local date). Shown as "Today · 10/06/2026", read-only |
| Existing note on the Notes page | Shown, read-only. A hint says: use the Calendar to put it on another day |
| New note on the Calendar | The day the user selected |
| Existing note on the Calendar | **Move to another day** (the shared date picker). Moving keeps `created_at` and sets `updated_at` |

- One date can have many notes.
- A date can't be cleared. The only way to take a note off the Calendar is to delete it.
- Rust enforces this: `update_note` takes no date, and `move_note` is the only function that changes one.

## The Note

| Field | Notes |
| ----- | ----- |
| `id` | Integer |
| `text` | Plain text, trimmed, 1 to 200 characters, without its `#tags`. Line breaks are kept |
| `date` | `YYYY-MM-DD`, **NOT NULL**: the day the note belongs to on the Calendar |
| `color` | One of nine: yellow (default), orange, red, pink, purple, blue, teal, green, gray, or a custom `#rrggbb` |
| `pinned` | Pinned notes come first on the board |
| `position` | The board order inside a group (pinned, or the rest). Smaller is first. Set by dragging; a new note goes first |
| `remind_at`, `reminded_at` | The reminder time (UTC) and when it was shown ([[F008]]) |
| tags | Up to 5 of the user's tags (table `note_tags`) |
| `created_at`, `updated_at` | UTC ISO 8601. Cards show the updated time in local time in the user's 12/24-hour format ([[F003]]) |

## The Paper Editor

Writing and editing happen on a **paper**: a flat sheet of note paper with a soft shadow. There is no dialog, backdrop or focus trap. `NotePaper.svelte` is the one editor for both pages.

| Where | How it opens |
| ----- | ------------ |
| Notes page | Its own route: `/notes/new` and `/notes/<id>`, so Back and the URL work |
| Calendar | Inside the day panel, in place of that day's list, with Back. Under 896px it takes over the page (no bottom sheet for editing) |

**The paper is only for the note.** Everything else is outside it, above, in this order:

1. **Back** and the **save status** (Saving…, Saved, or the problem)
2. A tool row: **Color**, **Pin**, **Remind me**, and **Delete note** on the right
3. The **date** row (read-only on the Notes page; **Move to another day** on the Calendar)

**Color** and **Remind me** open a dialog (the color swatches, or the reminder picker), never a panel in the page: the paper's container holds only the paper. Picking a color closes its dialog.

Then the **paper** holds the text, the tag suggestions while typing `#`, and the tag chips. The **counter** sits under the paper.

### Color, pin and reminder

- **Color**: nine paper colors, shown as dots, and a pipette dot for any custom color. The choice is part of the note and is autosaved. Each color has a light and a dark step (`--note-<id>` in `app.css`).
- **Pin**: pins or unpins at once. A newly pinned note goes to the top of the pinned notes.
- **Remind me**: quick times or a day and time ([[F008]]).
- On a note not written yet, a pin or reminder is remembered and applied when the note is created.

### Saving

- **Autosave** about **600 ms** after the user stops typing, **in order**: saves wait for each other, so an earlier save can never overwrite a later one (the rule of [[F001]]). A save that is still waiting when a newer one arrives is skipped, because the newer one carries everything (`domain/saveQueue.ts`).
- **Flush** on Back, on Esc and when leaving the page (any link, the sidebar).
- A **new note isn't created until it has text**. Leaving an empty new paper discards it.
- An **existing note can't be saved empty**. The paper says "A note needs some text. The last saved version is kept."
- If saving fails (or the text is over 200 characters), the text stays on the paper with the error, and Back stays on the paper so nothing is lost.
- Status line: Not saved yet, Saving…, Saved, or the problem.

### Delete and Undo

Delete has no dialog. The note is deleted, the user goes back to the list, and a notice offers **Undo** for a few seconds. Undo restores the note with its id, day, text, times and tags (minus any tag deleted in the meantime) (`restore_note`).

## Tags in a Note (`#name`)

| Rule | Behavior |
| ---- | -------- |
| Same tags as activities | One `tags` table, names unique ignoring case ([[F002]]) |
| Typing `#` | Opens suggestions: existing tags whose name starts with what was typed (ignoring case), plus "New tag #name" |
| Commit | **Space, Enter, comma or Tab**. Enter picks the highlighted suggestion (arrows move it, Esc closes the list) |
| After commit | `#word` leaves the text and shows as a chip under it. The text stays clean, and tags don't use up the 200 |
| Existing name | Reused, keeping its stored spelling (`#HEALTH` becomes the chip `#health`) |
| New name | Created as a new tag (no color) in the **same transaction** as the note |
| Chip × | Removes the tag from this note only; the tag stays in the list |
| Limit | **5 tags** per note ("A note can have up to 5 tags.") |
| Valid characters | Letters, combining marks and digits in **any script**, plus `_` and `-` (see below) |
| Not a tag | A `#` not at the start of a word (`C#`, `issue#42`) or not followed by a tag character (`# heading`, `#🎉`) stays plain text |
| On save | A valid `#tag` still in the text (for example the last word with no space) is committed the same way |

**Characters.** A tag character is judged per user-visible character (grapheme cluster): it must **start** with a letter or digit in any script, `_` or `-`. This is what makes `#สำเร็จ` work. Thai vowel and tone marks such as `็` and `่` are combining marks that Rust's `char::is_alphanumeric` rejects, but they always sit in the same cluster as their consonant. Emoji start with a symbol, so they are never tag characters. Tests cover Thai, Chinese, Japanese, Korean and emoji.

**One rule, two sides.** Rust (`notes::extract_tags`, `is_tag_char`, `tag_name`) is the authority. TypeScript (`domain/notes.ts`) mirrors it for the live chips, and **both run the same cases** from `crates/irontion-core/fixtures/note_rules.json`.

- Renaming a tag on the Activities page renames its chips on notes (chips show the tag's current name). Deleting a tag removes it from notes and keeps the notes.
- The Activities tags panel shows how many **activities and notes** use each tag.
- Note tags don't change the Insights time summaries. Notes are not time data.

## Counting Characters

The limit is `MAX_NOTE_LEN = 200` in `crates/irontion-core/src/lib.rs` (the authority), mirrored in `domain/notes.ts`. Length is the number of **extended grapheme clusters** (Unicode UAX #29) of the text **after** tags are taken out and it is trimmed: `unicode-segmentation` in Rust, `Intl.Segmenter` in the app. A Thai word with marks (ที่ is three code points), a CJK character, an emoji with a skin tone, a family emoji and a flag each count once. The text box has no `maxlength`, which counts UTF-16 units and would be wrong for Thai and emoji. The counter turns to the danger color over the limit, and nothing is saved.

## The Notes Page (the board)

- Sidebar item **Notes**. A **board** of paper cards, **as tall as their text**, in as many columns as fit (each at least 15rem wide). Cards are dealt into the columns **in order, left to right and then down**, so the reading order is the list order at any width.
- **Pinned** notes are a group at the top ("Pinned"), then the rest ("Others"). The headings show only when something is pinned.
- **The order is the user's.** **Click a card to open it; hold it and drag to move it** (no handle). Drop it on another card to put it before that card, inside its group; drop it anywhere else and it glides back. On touch, rest a finger on the card for a moment to pick it up; a quick swipe still scrolls. With a card focused, **Alt+Shift and the arrow keys** move it one place, and a screen reader hears "Moved to place 2 of 6." When a card is dropped, the others **slide** to their new places (see Animations in [[F003]]). A new note goes to the top.
- No sort control and no date headings: the user decides the order.
- A card shows the text, tag chips, a date chip (read-only) and, if set, a reminder chip. The **pin** button is on the top edge. Opening a card opens its paper (`/notes/<id>`).
- **Tag panel on the right** (a column from 896px): "All notes" and every tag some note uses, with counts, to show only the notes with that tag. Under 896px it moves **above** the board as one swipeable line of chips.
- **Search** (text and tag names, every word, any order, ignoring case) works with the tag panel. "Showing X of Y" and **Clear filters** (also when nothing matches).
- **While a search or tag is on, dragging is off** (a filtered list is only part of the order); clear it to reorder.
- **New note** opens a blank paper for today.

## Decisions

| Decision | Why |
| -------- | --- |
| **Every note has a date**; the Notes page writes today and never changes it; only the Calendar moves a note | A note always has a place on the Calendar, and there's one obvious place to change it |
| Notes page and Calendar are two views of the same notes | One `notes` store, one `NotePaper`, one set of rules |
| Paper editor instead of a dialog | A note is something you write on, not a form. The old dialog also clipped the date picker and drew a focus box on the paper |
| `#tags` leave the text and become chips | The text stays clean and the 200 characters are for writing |
| Notes reuse the activity tags | One vocabulary, one place to rename or delete |
| A tag character is judged per grapheme cluster, by its first character | Accepts Thai marks without a Unicode category table (none is available offline); rejects emoji |
| `#` must start a word | `C#` and `issue#42` stay as written |
| A tag still being typed at the caret is not saved by autosave | Otherwise a pause after `#wor` would create the tag `wor`. On Back, Esc or leaving it is committed |
| Autosave waits for each save (save queue) and skips stale ones | An earlier save can never land after a later one (F001's rule) |
| Delete with Undo, not a confirmation | Notes are small; Undo is faster and still safe (`restore_note` brings back the id, times, color, pin and reminder) |
| A failed or too-long save keeps the user on the paper | Text is never lost silently |
| **The board order is a stored `position`**, not a sort | The user wanted to arrange notes, not sort them. `reorder_notes` takes a whole group at a time; pinned notes always sort first, so the groups never mix. A new or newly pinned note takes the smallest position |
| Cards are **dealt into columns in turn** (round robin), not measured | Reading order equals list order at any width, and drag targets are simple. Cards are still as tall as their text. The cost: a very tall note can leave a gap in its column |
| The **whole card** is the drag handle: a click opens, a drag moves | A mouse drag starts after 5px and the click that ends it is swallowed. On touch the card is picked up after a short hold (280 ms), so a quick swipe still scrolls. Keyboard users move a card with Alt+Shift and the arrows |
| **Dragging is off while filtering** | A filtered list is only part of the order; reordering it would be ambiguous |
| **Tools are outside the paper** | The user asked that the paper be for the note only |
| Pin and reorder are **not edits** (`updated_at` stays) | They arrange the board; "updated" means the text, tags or color changed |
| **Nine colors**, fixed ids with theme tokens | Works in light and dark, and the core can validate a short list. A free color is left as an idea |
| **No templates** (removed by migration 006) | The user wanted to write freely, like a real sticky note. Migration 006 drops the column; text, days and tags stay. (A first version had six templates and a Calendar deadline mark; both are gone.) |
| **Migration 005 rebuilds the table** instead of editing 002 to 004 | 002 to 004 already ran on real databases. Undated notes get the local day of `created_at`;  `note_tags` is copied aside so the rebuild doesn't cascade-delete links |
| Spec files are in `irontion_docs/features/` | Where F001 to F005 live |
