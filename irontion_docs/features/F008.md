# F008: Reminders

A reminder tells the user about a note at a time they chose. It is **its own feature**, not part of the Calendar ([[F007]]): the Calendar answers "which day is this note on?", a reminder answers "when should I be told?". Any note ([[F006]]) can have one reminder.

> [!info] Overview
> - Set it on a note's paper: the **Remind me** tool opens a dialog with quick times or a day and a time
> - A **Reminders** page (sidebar item) lists notes that have one: **Upcoming** and **Past**
> - When the time comes, a **notice** appears and **stays until dismissed**, with an **Open note** button. It is shown **once**
> - Reminders show **while Irontion is open**. They do not reach the user when the app is closed (see Open Questions)
> - Times are stored in **UTC** and shown in local time, in the user's date and 12/24-hour format ([[F003]])

## Setting a Reminder

| Choice | Time |
| ------ | ---- |
| In 1 hour | One hour from now, seconds dropped |
| Tomorrow morning | Tomorrow at 09:00 local |
| Next Monday morning | The coming Monday at 09:00 local (a full week away on a Monday) |
| Day and time | The shared date picker (a dialog) and a time field. **Set reminder** is disabled for a time in the past, with no hint text |

- Choosing a time sets it at once. **Remove reminder** clears it.
- The Remind me button shows the time when one is set; a card shows a bell chip with the time (accent color while upcoming, muted once past).
- Setting a reminder again makes it **due again**, even if the earlier one was shown.
- Setting or clearing a reminder is **not an edit**: the note's `updated_at` stays.
- On a note not written yet, the reminder is applied when the note is created.

## When It Is Due

- While the app is open it asks the backend **every 30 seconds**, and once at start, which reminders are due (`remind_at` has passed and `reminded_at` is empty).
- Each due reminder is shown **once**: a notice "Reminder: <the note's text>" with **Open note**. The notice has no timeout. The backend marks it as shown (`reminded_at`), so it never comes back unless the user sets the reminder again.
- A reminder set in the past by other means is shown at the next check.
- Checks never overlap (a slow check is not started twice).

## The Reminders Page

| Part | Behavior |
| ---- | -------- |
| Upcoming | Soonest first |
| Past | Most recent first. These were shown or are overdue; the user clears them when done |
| Each item | The note on paper (opens its paper) and **Clear reminder** below it |
| Empty | Explains how to set one, with a button to the notes |
| Clock | The page moves a reminder from Upcoming to Past while it is open |

The sidebar and drawer list **Reminders** after Notes. On a phone it is under **More** ([[F004]]).

## Rules (enforced in Rust)

| Rule | Error kind |
| ---- | ---------- |
| `remind_at` is UTC, `YYYY-MM-DDTHH:MM:SS` with optional milliseconds and a trailing `Z`; real date, hour 0-23, minute and second 0-59 | `invalidReminder` |
| The note must exist | `notFound` |
| It is stored in one shape (`...SS.fffZ`) so times compare correctly as text | |

A time in the past is accepted by the core (the UI refuses it); it simply becomes due.

## Behavior

- [x] Set a reminder on a note: three quick times, or a day and time
- [x] Clear a reminder, from the paper or the Reminders page
- [x] A due reminder shows as a notice that stays, once, with Open note
- [x] Reminders page with Upcoming and Past
- [x] Reminders on the cards, in light and dark, all five languages, 390px to wide
- [x] Undo after deleting a note brings its reminder back
- [ ] **System notifications when the app is closed** (needs the Tauri notification plugin and a background process)
- [ ] Snooze ("remind me again in 10 minutes")
- [ ] Repeating reminders (daily, weekly)
- [ ] More than one reminder per note
- [ ] A time-of-day setting for "morning" (fixed at 09:00 today)

## Decisions

| Decision | Why |
| -------- | --- |
| Reminders are a feature apart from the Calendar | The user asked for it: the Calendar is a day view of notes; a reminder is a moment in time |
| One reminder per note, stored on the note (`remind_at`, `reminded_at`) | Simple, and enough for sticky notes. No extra table |
| Polling every 30 seconds in the app | There is no background service. 30 seconds is precise enough for a sticky note and costs almost nothing (one indexed query) |
| The backend decides what is due (`due_reminders`) and records that it was shown | One source of truth; a restart doesn't show an old reminder again |
| The notice is **sticky** | A reminder that fades after 4 seconds is easy to miss |
| In-app only for now | The Tauri notification plugin is not available in this environment, so native notifications are an open item rather than a half-working one |
| Local time in the UI, UTC in storage | Time zones and clock changes don't corrupt stored reminders |

## Implementation

- Migration `crates/irontion-core/migrations/007_notes_board.sql` (`remind_at`, `reminded_at`, index `notes_remind`)
- Rules: `crates/irontion-core/src/notes.rs` (`set_reminder`, `due_reminders`, `mark_reminded`) and `validate::timestamp`, unit-tested
- Commands: `set_note_reminder`, `due_reminders`, `mark_note_reminded` in `apps/desktop/src-tauri/src/commands.rs`, with an IPC test; both backends in `apps/desktop/src/lib/api/`
- Pure logic: `apps/desktop/src/lib/domain/reminders.ts` (quick times, local and UTC, split into upcoming and past), unit-tested
- Watcher: `apps/desktop/src/lib/stores/reminders.svelte.ts`, started in `routes/+layout.svelte`; sticky notices in `stores/notices.svelte.ts`
- UI: `components/notes/ReminderPicker.svelte`, `routes/reminders/+page.svelte`

## Open Questions

- Should reminders also reach the user when the app is closed (a system notification, or a tray icon that keeps running)?
- Should a past reminder be cleared automatically after the user opens the note?
